## 本机 PowerShell 完整操作

构建已完成的交付目录是 `F:\溪泉洗浴系统\最新版安装包-账号与小票-0.5.0`。下面在本机 PowerShell 执行，不在 ECS 的 Bash 中执行。云端会暂停使用几分钟，先通知所有收银/服务终端不要继续下单。不会清空会员、次卡、余额、订单、库存或审计。

```powershell
& {
    $ErrorActionPreference = 'Stop'
    Set-Location -LiteralPath 'F:\溪泉洗浴系统'
    $delivery = 'F:\溪泉洗浴系统\最新版安装包-账号与小票-0.5.0'
    powershell.exe -NoProfile -ExecutionPolicy Bypass `
        -File (Join-Path $delivery '01-部署云端.ps1')
    if ($LASTEXITCODE -ne 0) {
        throw '云端未完成，停止。保留 PRIVATE_DESKTOP_JOB 和 FAILED_PHASE，不继续发布。'
    }
    powershell.exe -NoProfile -ExecutionPolicy Bypass `
        -File (Join-Path $delivery '02-签名并发布桌面更新.ps1')
    if ($LASTEXITCODE -ne 0) {
        throw '签名或发布未完成，请保留输出和现有安装包。'
    }
    Start-Process explorer.exe -ArgumentList ('"' + $delivery + '"')
}
```

第一步提示时输入 `UPDATE 0.5.0`。脚本自动使用唯一的新 stage，不用手打随机路径；云端会先校验全部源文件 SHA256、实际备份并恢复隔离副本，验证账号身份、原数据、专用数据库角色和小票清理，再迁移两条新结构并做后备份恢复。所有者命令与恢复容器各256MiB、余量128MiB，共640MiB，并重新读取实际内存。任何 gate 失败会保留原证据，不自动恢复旧数据库。

第二步先从云端读取本次 `completed.json` 并核对源码 SHA256/commit、精确新镜像、API 和私有小票清理任务健康；不能只口头确认成功。验证后输入 `PUBLISH 0.5.0`，再在隐藏提示输入原桌面发布密钥密码（不要发送到聊天）。四个通道可能分别提示一次密码。私钥固定保存在 `F:\溪泉洗浴系统\private\溪泉发布密钥\desktop-release-private.pem`，绝不进入交付目录或 GitHub。发布序号取大于线上已验证签名序号的值，沿用原最小版本和信任公钥，不猜序号1。

升级后旧 0.4.9、0.4.8 和使用原信任的仍受支持旧版，退出回到登录页，点“检查更新”，下载并覆盖安装；不要卸载、删除终端设置。四个现代通道和历史 x64 下载入口会更新，未请求的 Win7 策略、手机和网页版本策略不会被覆盖。

## 若云端中途停止

只在同一交付源、同一私有任务上续跑。用失败输出中的确切 Stage/Job 替换两项，不使用旧 operations/stock/049 脚本，不关闭维护，不手改数据库。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
    -File 'F:\溪泉洗浴系统\最新版安装包-账号与小票-0.5.0\01-部署云端.ps1' `
    -Mode resume `
    -Stage '/opt/xiquan-releases/desktop050-stage-此处替换为32位实际值' `
    -Job '/opt/xiquan-backups/desktop050-cutover-此处替换为32位实际值'
```

迁移已经完成但 after 备份未验证时，只补备份验证，不重复迁移。已释放维护时只验证精确新服务，不重新挂维护或恢复数据库。部分备份保留为私有 retained 目录。迁移结果没有确切 after 证据时会停止并要求定点诊断。

## 验收

普通员工删除后可用同手机号重新注册，但新账号 UUID 不继承旧交易；最高管理员/本人不得删除。所有桌面岗位都有本人改密入口，修改后旧 access/refresh/socket 全部失效。男/女搓澡师、三楼服务员加单会用下单电脑选定的58mm打印机打印该批项目，突出手牌及员工；其他岗位加单不自动打印。

小票补打有两类独立数据：服务岗位只有权限范围内下单票，普通收银岗位只有结账票，最高管理员可看两类。当天成功、失败、待打印均可补打。北京时间午夜后仅过期票/打印尝试被清理，历史订单/金融/责任身份/注册与审计证据保留。重复加单请求和打印失败都不会再次扣款或扣库存。

本地自动化与源码校验不能代替真机验收：请用 XP-58 实打一次，断开USB再加单确认业务成功但打印失败可补打；在另一台电脑旧版登录页检查覆盖升级，并验证手机1.2.9原有登录、注册令牌入口。实体PG17演练只在云端隔离副本执行，不冒充本机测试。
