# 手机端 1.2.9：应用内更新安装路径修复

## 原因与修复

已用组件回归复现截图中的错误：安卓下载器的最终进度通知在 UI 线程异步发送，可能晚于下载 Promise 完成。旧状态机把这条迟到通知当成新下载，清空了已验证 APK 路径；权限查询完成后，安装函数读取到空路径，原生目录安全检查因此拒绝安装。

本次仅修复手机更新状态机：下载完成、等待授权或进入安装后忽略迟到进度；安装函数在查询系统权限前保存明确的 APK 路径。保留 HTTPS、SHA256、原签名和原生更新目录限制，不通过放宽目录校验来规避问题。

版本为 1.2.9，versionCode 16，最低允许版本仍为 9；注册令牌功能保持。发布程序保留 1.2.8 APK 与旧页面资源，仅更新 Android 发现策略和移动页面，不重启 API，不修改数据库或桌面发布策略。

## 旧版恢复限制

旧 APP 的更新页面和代码随 APK 打包，并非从云端动态加载。新的 APK 无法先修复正在运行的旧更新器。能完成应用内安装的手机可直接覆盖更新；已持续出现此错误的手机，需要从官方地址下载 1.2.9 后做一次系统覆盖安装，不能先卸载。之后使用修复过的应用内更新器。

## 本机构建与发布

交付目录：`最新版安装包-安装器修复-手机版1.2.9`。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "F:\溪泉洗浴系统\最新版安装包-安装器修复-手机版1.2.9\01-构建并发布手机修复.ps1"
```

按隐藏提示输入原安卓证书密码；发布确认输入 `PUBLISH ANDROID 1.2.9`。默认用本机真实的 1.2.8 APK 校验签名连续性。脚本先构建并校验，再上传；任一步失败则停止。

正式 APK 生成后路径：`F:\溪泉洗浴系统\release\mobile\xiquan-mobile-ordering-1.2.9.apk`，并复制到交付目录。不能把旧安装包改名为新版本。

## 验收

用出现故障的手机覆盖安装后确认版本为 1.2.9；两个授权管理员底部仍有“注册令牌”。下一版更新时检查：下载完成后正确打开系统安装确认，授权页面往返和迟到进度不再把安装路径清空。未安装到实机前，本地测试不等于实机验证。
