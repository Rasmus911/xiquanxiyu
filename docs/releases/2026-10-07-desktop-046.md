# 组合收款与三端更新交付

桌面新版 0.4.6；安卓新版 1.2.4（versionCode 11）。支持 Win10/Win11 的 x86、x64 四个安装目标，不构建 Win7。

## 用户实际操作

先在本机 PowerShell 依次运行交付文件夹的三段指令。不要在 ECS 的 Linux 窗口运行 PowerShell。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "F:\溪泉洗浴系统\最新版安装包-组合收款-0.4.6\01-部署云端.ps1"
```

确认输入 `UPDATE 0.4.6`。自动获取本次新暂存路径，在原服务仍正常时准备新镜像；然后暂停写入，完成备份、隔离恢复验证、数据一致性检查，切换代码及网页后恢复服务。整个备份验证阶段也属于维护时间，请勿继续开单。不会重放以前的库存部署任务，不执行数据库结构修改，不清空账号、订单、余额、库存或审计记录。需要现有云端已经完成 0.4.5 后端更新，对应 schema `20261007_desktop_ops`。本次仍有密码验证及发布签名人工步骤，未执行指令不表示已经上线。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "F:\溪泉洗浴系统\最新版安装包-组合收款-0.4.6\02-签名并发布桌面更新.ps1"
```

确认输入 `PUBLISH 0.4.6`，使用原桌面发布私钥，不创建新密钥。必须读取、验证现有四个正式通道，序号在最大现有序号基础上递增，不能猜测序号 1。原密码通过隐藏提示输入，不要发到聊天里。

桌面 0.4.4/0.4.5 关闭后重开，约 15 秒检查原更新通道；0.4.5 登录页可点“检查更新”。联网下载后确认覆盖安装，不卸载、不改变安装标识。发布仍保持旧版最低版本策略，按原操作系统和架构通道下载。未发布签名通道时，已有安装不会凭空看到本地改动。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "F:\溪泉洗浴系统\最新版安装包-组合收款-0.4.6\03-构建并发布安卓应用内更新.ps1"
```

确认输入 `PUBLISH ANDROID 1.2.4`。本机原证书密码隐藏输入，构建正式 APK，核对应用 ID、versionCode 和原证书指纹，再上传发布。默认使用原 `private\android\xiquan-mobile-release.jks`，会自动找本机旧正式 APK 作为证书参考；找不到可给脚本加 `-PreviousApkPath "旧APK完整路径"`。不允许换证书要求用户卸载。保留桌面/网页策略、旧 APK 和 Nginx 配置，安卓策略只更新安卓段。

旧安卓 APP 已带原生更新器的版本（例如 1.2.2/1.2.3）打开或点“我的→检查应用更新”，应用内下载、进度显示、SHA256 校验，再弹系统覆盖安装确认。首次需要允许“安装未知应用”，返回 APP 后继续安装。不会跳转下载网页。新 1.2.4 登录页也可检查更新。完全没有原生更新器的早期包不能仅靠服务端增加原生安装能力，需单独核对实际旧包版本，不承诺静默安装或绕过 Android 安装确认。

## 收款验收

1. 160 元账单填写现金 20、支付宝 40；输入会员完整手机号，查到余额 100，点“使用可用余额”：合计 160，会员变 0，结账一次。
2. 默认现金 160，会员余额 100：点使用余额后，现金重分配为 0，余额填 100，明确显示仍需收款 60。点微信/支付宝“补齐剩余”后再结账。
3. 手动填写现金、支付宝的金额不会被使用余额按钮抹掉；未使用的零金额行不提交。
4. 少收、多填、负数、非法精度、会员不足不能确认；后端最终校验、并发锁及幂等请求继续生效。
5. 重复点击/网络重试不得重复扣款。小票列出各方式，报表会员消费和本次外部收款分开，充值不重复计入消费营收。微信/支付宝仍为收银员确认到账后记账，并非自动发起第三方扣款。
6. 本轮安卓同步现有手机权限、库存和项目等适用改动，不新增收银员/搓澡师手机收款权限；收款仍在原有桌面/网页收银端，所有端共享同一 ECS 数据。

## 交付边界

本地验证、安装包构建及源代码封装不等于云端已部署。正式桌面更新签名、安卓原证书构建、PG17 隔离恢复和实机覆盖安装/打印验收由以上人工指令完成。失败保留输出与私人备份目录；不要删备份、回放旧部署、清空维护标记或直接恢复数据库。
