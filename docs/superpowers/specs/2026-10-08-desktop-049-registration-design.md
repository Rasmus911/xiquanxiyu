## 2. 现有机制与选择

现有登录页 `client/src/views/LoginView.vue` 已有“检查更新”，Electron 已有下载、签名校验和覆盖安装流程。现有 Flask 员工表、岗位权限和入口策略可以复用；手机个人页、路由和会话能力可以承载独立授权码页面。

采用服务器统一生成、受限手机会话在线查看的共享授权码，不采用两台手机各自保存密钥的离线令牌。统一状态便于立即消费、同步失效及撤销权限，不存在手机时间不同导致各自显示不同码的问题；云端不可用时授权码功能不可用。

授权状态和限流保存到独立数据库表，重启不重置；员工创建复用既有密码哈希和权限模板，不开放现有最高管理员创建接口。不得通过本次功能更新既有最高管理员 UUID 策略。

## 3. 注册交互

“注册账号”仅在桌面登录页展示。弹窗填写手机号、姓名、岗位、密码、确认密码和管理员提供的6位授权码。提示“请向管理员获取手机端注册授权码，每180秒更新，注册成功后立即更换”，不再显示发送短信或重新发送按钮。

注册成功后关闭弹窗、清除密码和授权码，将注册手机号填入登录账号栏，由用户自行登录；不自动签发登录令牌。提交期间禁止重复点击；关闭弹窗后迟到的请求结果不得覆盖登录状态。超时后先核对是否已创建账号，不盲目重复请求或重复消费授权。

前端校验只是提示，服务器独立校验全部字段。若网页或手机直接请求注册接口，拒绝其入口声明；新账号的真实可用入口始终由后端权限策略限制为 desktop。此机制不等同于对任意第三方客户端作不可伪造的设备认证，也不证明员工本人持有该手机号。

在两位指定管理员手机端“我的”页面增加“注册授权码”入口，打开独立页面，显示分组数字、180秒有效期倒计时和说明。只在页面可见且应用前台时刷新；网络中断、退出页面、切换账号、会话撤销或退出登录时立即清掉明文码。手机从后台回到前台必须先重新查询服务器，不能继续展示缓存码。

服务端响应携带授权代次、服务器时间和到期时间，两端以服务器时间计算倒计时；注册成功后的换码使用受限通知和不超过5秒的页面轮询同步，两端最终以同一服务器代次为准，不承诺网络传播零延迟。通知只表示需要刷新，不能向全员业务广播发送授权码。除这两个账号以外，包括 `15133863898`，均不展示入口，直接调用接口也必须被拒绝。

## 4. 后端接口与数据

新增受保护的 `POST /api/auth/registration-token/current`，只接受已登录且入口为 mobile 的会话。每次重新核对账号启用状态、会话版本、实际 UUID、当前权限策略保护绑定和指定用户名，不能只看姓名、角色或客户端 capability。响应只对这两个账号返回 `code`、`generation`、`server_time`、`expires_at`；添加 `Cache-Control: no-store`，不缓存到本地存储、服务工作线程或第三方日志。

新增公开 `POST /api/auth/register`，接收 `username`、`display_name`、`role`、`password`、`code`、`terminal_code`、`client_channel='desktop'` 和幂等请求编号。拒绝未知权限、安全状态字段及其他岗位；核对终端已登记且启用。相同手机号包括已软删除账号在内不允许覆盖注册，改走既有管理员维护流程。成功返回“注册成功，请登录”，不返回 access/refresh token 或密码哈希。

共享授权状态包含授权代次、非秘密随机种子、到期时间、错误次数和消费信息。6位码使用专用服务器密钥对代次和种子作域隔离 HMAC 派生；数据库、审计、桌面包和 APK 均不保存明文授权码或派生密钥。密钥缺失时只让此功能返回配置错误，不把整个 API 启动关闭。原会员短信配置不作为注册必需条件。

到期换码及成功消费均锁定授权状态行，使用数据库事务串行执行。成功注册的员工创建、固定权限、旧授权消费、新授权生成、幂等回执及审计一起提交；手机号唯一约束负责兜底并发冲突。同一旧码的并发注册最多一个成功。刚换出的码不得与上一代相同。服务器重启保持有效期和消费状态；数据库异常不能返回注册成功。

幂等回执绑定请求编号、终端与服务端带密钥的请求摘要，不能明文保存密码或授权码，也不能存储可供离线猜测的普通密码摘要；重复成功请求只返回原成功结果，不再次消费新码、不再次创建账号。相同请求编号但资料不同必须拒绝。输错次数和冷却作为独立持久安全事件提交，不能因为注册事务回滚而清零。

## 5. 防滥用、权限与追责

注册校验按终端及来源限制为10分钟最多10次；单代授权码全局最多5次错误输入，达到上限后该代不再接受注册，180秒自然到期后换码。错误次数、限流和幂等记录持久化，不能靠改手机时间、刷新页面或重启服务绕过；未经授权的手机查看不能生成或更换授权码。来源识别必须沿用可信代理设置，不能相信客户端任意伪造的 IP 头。

服务器只接受上述三个岗位，硬编码新账号可用入口为桌面；岗位权限沿用现有最小权限，不因“启用”自动获得管理员能力。保持维护屏障和数据库角色权限，新增表采用加法迁移并补充必要授权、屏障触发器；正常 API 启动不得自动迁移。

审计记录授权码页面的访问会话、授权代次变化、校验失败与注册成功，关联查看者 UUID、请求编号、终端、代次和新员工编号；不记录明文密码、授权码、密钥或原始敏感请求体。自动轮询不逐次写重复查看审计，按会话和授权代次去重。失败事件不能冒用尚未创建的员工为操作人。

共享授权码不能唯一证明是哪位管理员向员工提供的；审计明确区分“哪些管理员查看了该代授权码”和“哪个终端创建了账号”，不得伪造唯一审批人。注册用途限定于上述三个普通岗位，不用于付款、重置经营数据或管理员注册。

## 6. 手机权限与会员短信保持

不添加 `SMS_REGISTRATION_TEMPLATE_CODE`，不需要注册短信模板。两位管理员的登录、原有手机功能和既有 UUID 绑定保持不变，只增加受限的 `registration_token_view` 会话能力；web/desktop 入口会话不能读取授权码。手机导航提示只是显示控制，授权由服务器重新检查；入口声明不等于不可伪造的设备证明。

新增专用服务器密钥配置 `REGISTRATION_TOKEN_SECRET`、私密备份和缺失检查，使用至少32字节的安全随机值，重复部署保留既有值，发布包不包含真实值。不能在聊天、GitHub、安装包或公共页面放密钥和真实令牌；不提供万能码、开发绕过或角色升级捷径。

会员检查覆盖首次储值开卡、每次新次卡、后续普通充值、支付请求重试、参数金额/次数、客户及管理员收件人、发送拒绝与异常提示。金融交易已成功时短信失败必须明确提示，但不能再次扣款或重复发卡。SDK接受只标记“已提交运营商”，不冒充“已送达手机”。

此前两项隔离自动化测试曾通过，只证明当时的会员开卡触发条件和模板参数，不能代替本次回归结果；真实发送及手机送达需云端配置和实机确认，不纳入未执行的完成声明。
