# 0.5.4：手牌芯片绑定与刷卡开牌设计

日期：2026-10-13，北京时间。用户已确认聊天中的完整方案：前台页面刷卡开牌、60 秒滑动联动，以及位于“系统设置”下方的独立手牌 ID 录入页面。本文件用于书面设计复核，尚未代表实现、构建、签名或上线完成。

## 1. 目标和边界

- 桌面与网页版本为 0.5.4；保留 Win10、Win11 的 x86/x64 四个更新通道，不做 Win7。
- 登录页仍可检查更新，旧版经已有签名通道及旧版过渡入口下载安装新版本。不得清空防回退状态、取消验签或替换原发布密钥。
- 更新日志原文：`1.用ID卡读取手牌号来实现开牌的效果`。
- 当前 100 个有效手牌：男浴 `001–050`，女浴 `051–100`。不重编号，不创建额外手牌；历史已退役号码不纳入录入列表。
- 自动开牌使用服务器当前启用的普通门票，金额不由读卡器或客户端提供；原有人工开牌及儿童门票选择继续保留。
- 所有开牌、门票、联动、审计和数据同步通过云端业务事务完成；不得仅改变本机卡片颜色。
- 本机开发，不由代理连接 ECS。实际生产部署由用户运行交付 PowerShell；没有读取到的新云端状态不得写成已验收。

## 2. 方案选择

采用云端一对一绑定。每台电脑读取芯片 ID 后交给同一服务器识别手牌，避免逐机维护不同的绑定。相比本机配置文件，这种方式支持一致性、权限和追责；相比按芯片 ID 尾号推断手牌号，它不依赖读卡器编号规律。

芯片 ID 是业务标识，不是员工登录凭据或防复制凭据。读卡设备可能模拟键盘输入，本次先沿用系统现有数字卡号加 Enter 的接入方式；真实设备输出格式、速度与可复制性仍需实机验收，不承诺普通 ID 卡具备防克隆能力。

## 3. 手牌 ID 录入页面

- 桌面/网页左侧新增“手牌ID录入”，在菜单排序上紧随“系统设置”，在“账号密码修改”之前；独立路由 `/wristband-bindings`。
- 仅前台收银员 `cashier` 和现有最高权限绑定人员可查看、录入、修改、解除绑定。库管、普通经理、搓澡师、三楼服务员不因已有开牌权限而获得本页面。
- 最高权限沿用现有 UUID 授权策略，不按姓名、手机号字符串或客户端传入角色提升权限。
- 收银员只获得这个独立页面及对应 API 权限，不因此看到或操作其他系统设置。
- 列出 100 个有效手牌，按男女浴筛选、按号码搜索；列为手牌号、浴区、绑定状态、芯片 ID、最近修改时间和操作。显示已录入/未录入数。
- 录入操作：选择手牌，打开刷卡输入框，读取数字 ID，明确保存；此页面刷卡仅录入，不自动开牌。
- ID 保存为 1–64 位 ASCII 数字字符串，保留前导零；仅去除读卡终止换行和首尾空白，不做数字转换或截取尾号。
- 同一芯片 ID 不得绑定不同手牌，一个手牌仅有一个当前绑定。重复保存完全相同的绑定返回已绑定，不重复写入。
- 首次绑定不要求额外密码；更换或解除绑定必须验证当前登录账号自己的密码。已激活、挂失、结算中或停用手牌不能更改或解除绑定。
- 所有修改都在服务器检查身份、状态与唯一约束，并留下修改前后 ID、手牌号、员工身份、终端和请求 ID；密码不得写入日志。
- 绑定属于物理资产配置，经营数据重置保留这些绑定；库存继续按既定规则保留，会员等其他内容沿用现有重置范围，不借本次功能改变重置范围。

## 4. 前台刷卡接收

- 前台手牌页面显示“准备刷卡”状态和“刷卡联动”开关。页面处于前台且登录账号具有 `visit_open` 时监听数字读卡序列，不要求点击某张手牌。
- 输入监听只属于这个页面；离开路由、隐藏窗口、退出登录、经营期变化、维护或权限变化时清理缓冲与联动上下文。返回页面重新准备，不能接续旧上下文。
- 普通鼠标点击、Tab、Enter、Esc、数字搜索等原有键盘操作必须保持。弹窗及普通编辑输入时不自动开牌，提示“操作完成后恢复刷卡”；不抢密码、备注或会员卡输入。
- 读卡序列与人手键盘输入分离：收集快速连续数字并以 Enter 终止；慢速或不完整序列不提交，显示可重新刷卡的状态。阈值须通过设备样本验收，不能将普通手牌搜索回车当成芯片刷卡。
- 通过完整序列识别后串行处理刷卡请求；请求未完成时后续有效刷卡排队，不因为 `loading` 丢掉下一张。限制队列长度并对溢出明确提示重新刷卡。
- 没绑定、已退役、挂失、停用或结算中的手牌返回明确错误，不自动补绑定或恢复。
- 已激活手牌重复刷只提示“已激活”，不新建订单、不再次计门票、不擅自关联已有顾客；重复刷不延长联动时间。
- 断网、超时或失败不显示成功，不在离线状态积累日后自动开牌；同一请求重试使用相同幂等身份，避免请求已成功但响应丢失造成重复开牌。

## 5. 滑动 60 秒刷卡联动

- 联动开关默认关闭；不开启时每张新手牌独立开牌。
- 开启后第一张成功开牌建立当前联动组；之后成功刷入的新手牌在服务器计时的 60 秒窗口内加入该组，可跨男女浴。
- 每次成功加入一个新手牌，窗口结束时间更新为该次成功时间加 60 秒。界面显示当前号码、人数和剩余秒数。
- 无操作达到或超过 60 秒，当前接收窗口结束，已开牌人员继续保持联动，不解除账单关联；下一张成功刷卡建立新的组。
- 关闭开关、离开页面或重新登录，仅结束接收窗口，不清空或拆分已经形成的联动组。
- 未知卡、失败请求和重复已激活卡不重置计时。迟到请求由服务器时间判定，不由客户端传入任意时间决定。
- 会话绑定当前员工、终端、经营期和随机会话标识。不同电脑、账号或页面会话不共享计时，不能传入他人的组 ID 把账单联动。
- 如果组内发生结账、清空、手动更改联动或其他业务状态变化，则结束原接收窗口；下一次开牌另建组，避免把新顾客插入已变化的账单。
- 原有手动联动、合并结账、联动后单独结账和单张强制清空保持原行为。自动刷卡组不受旧页面一次多选 20 张的限制，最多覆盖当前 100 个有效手牌；不借此取消手动批量接口的既有限制。

## 6. 服务端与数据库

- 新增 `wristband_chip_bindings` 表：当前手牌与当前芯片 ID 的双唯一绑定、版本及修改人员。业务不接受客户端传入金额。
- 新增 `wristband_scan_sessions` 表：会话标识、员工、终端、经营期、当前组、窗口时间及关闭状态，用于云端超时和会话隔离；不存储员工密码。
- 独立 API：绑定列表、录入/更换、解除；刷卡开牌 API 接收 ID、联动开关/会话标识及既有幂等请求身份。
- 保持现有维护屏障、财务写入锁、手牌及活动订单行锁、经营期和唯一索引。新开牌和门票计费、联动、会话更新时间、审计必须同一事务成功或失败。
- 绑定替换与刷卡开牌必须使用一致的锁顺序；数据库唯一约束兜底冲突，不仅靠先查询后插入。
- 通过既有 `wristbands.changed` 实时事件让其他桌面、网页和手机刷新；只向有相应权限的会话发送信息。手机服务人员仍只能对已激活手牌下单，不能经新 API 开牌或维护绑定。
- 本次为加法迁移，目标 revision `20261013_wristband_chip`，接续 `20261012_physical_membership`。不重建生产数据库，不清空业务、身份、卡余额、次数、库存、审计或已有绑定策略。

1. 最高权限人员和收银员可维护绑定；库管、普通经理、服务人员与未登录请求均不能绕过路由或直接调用 API。

3. 单张刷卡只开一次并生成一份普通门票；重复刷、请求重放、响应丢失重试与多终端同卡不重复收费。
4. 联动在 59 秒内加入、每次成功重置、60 秒边界另起组；未知卡和重复卡不重置；跨男女浴、离开页面和账号切换正确处理。
5. 模拟快速刷多张不丢单、慢速键入和普通 Enter 不误开牌；弹窗、会员卡输入、隐藏窗口不监听，返回前台恢复。读卡器本体仍需用户实机刷卡验收。
6. 成组后可统一或单独结账；单张清空不影响其他人；中途结账或改变组状态后新的卡不加入旧组。
7. 真正 PostgreSQL 环境验证行锁、唯一约束、重复开牌并发、维护屏障、权限和审计；SQLite 测试不能替代这些证明。
8. 迁移前后会员余额/次数、库存、订单、人员权限与审计证据按保护规则对比，快照必须真实恢复过。
9. Win10/Win11 对应架构旧版本经原更新通道下载并覆盖，Android 原证书覆盖安装，网页和手机同步消费；设备不在本机时明确标为未验收。
