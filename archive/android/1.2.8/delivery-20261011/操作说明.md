## 在本机 Windows PowerShell 顺序运行

先更新云端权限返回（会短暂重启 API，无数据库迁移）。提示时输入 `UPDATE TOKEN`：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "F:\溪泉洗浴系统\最新版安装包-注册令牌-手机版1.2.8\01-修复云端令牌权限.ps1"
```

第一步成功后，构建并发布安卓应用内更新：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "F:\溪泉洗浴系统\最新版安装包-注册令牌-手机版1.2.8\02-构建并发布手机更新.ps1"
```

按隐藏提示输入原证书的 keystore 密码和 key 密码，密码不要发到聊天里。发布确认输入 `PUBLISH ANDROID 1.2.8`。

需要分开执行时，第二个脚本支持 `-Mode build`（只构建，不上传）、`-Mode publish`（构建成功后上传）以及 `-Mode validate`（只检查本机条件）。

正式 APK 构建成功后会放在本目录，文件名 `xiquan-mobile-ordering-1.2.8.apk`。当前本目录不伪装成已经有正式 APK；签名需要你本机输入密码。

## 更新后检查

1. 旧 APP 内检查更新，联网下载并确认覆盖安装，不用卸载。
2. 任一授权手机号登录后，底部找到“注册令牌”。
3. 返回手牌、刷新数据，再查看入口是否仍在。
4. 另一授权手机号在同一周期看到相同令牌；其他账号看不到入口。

本地修复不代表已经云端上线。第一步若报连接超时，先恢复本机到 ECS 的 SSH 连接；不用更换证书，也不要运行旧的整库部署/恢复脚本。

## 如果原脚本停在上传 100%

先按 Ctrl+C 停止尚未执行补丁的旧上传，再重新运行第一步。当前脚本不再调用 SCP：通过 SSH 直接上传并在同一连接内校验哈希。输出中依次可见 `UPLOAD_AND_VERIFY`、`FILE_VERIFIED`、`EXECUTE_VERIFIED_API_PATCH`。小文件最多等待 90 秒，每 15 秒提示等待时间；超时会停止，不会自动进入后续部署或手机发布。

脚本会校验本次 Git 源码提交和真实 APK 签名，保留私有备份、旧 APK 和旧页面资源；不会把新 Android 更新策略覆盖成旧桌面策略。
