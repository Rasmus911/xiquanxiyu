# 溪泉洗浴历史版本归档

源码按 `desktop/<版本>/source-<版本>.zip` 分类；安卓安装包按 `android/<版本>/` 分类。

历史桌面安装包位于 `desktop/<版本>/installers/`。为避免超过单文件上传大小，安装包使用最多 **32 MiB** 的 `.part001`、`.part002` 等原始字节分片，不是独立安装程序。

## 恢复桌面安装包

下载同一版本 `installers` 文件夹内的全部分片、`parts-manifest.json` 和 `合并归档安装包.ps1`，放到同一个本机文件夹。在该文件夹执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\合并归档安装包.ps1"
```

脚本先验证每个分片的字节数与 SHA256，再按序合并，最后验证完整 EXE 的字节数及 SHA256。校验失败不要安装；脚本不会覆盖不匹配的既有 EXE。

GitHub Releases 中已发布的完整安装包也可直接下载。`versions.json` 记录版本及完整包校验信息；分片清单记录各分片校验信息。历史版本仅用于归档，不会替代 ECS 的正式更新通道。

## 不公开的内容

原签名私钥、安卓证书及密码、真实数据库与备份、私有环境配置、经营库存照片、含个人或经营数据的诊断记录均不上传此仓库。可重新生成的解压运行时、依赖缓存和失败构建目录也不作为版本归档。

本仓库保留历史版本，不作为正式更新服务器。当前待发布版本为桌面/网页 0.5.3、安卓 1.2.10；最新版文件保留在开发机。是否完成线上正式发布，应以 ECS 更新策略与实际设备检查为准，不以本归档判定。

## 2026-10-12 历史归档分类

- `desktop/0.5.1/`、`desktop/0.5.2/`：各版本分别按 `win10-x86`、`win10-x64`、`win11-x86`、`win11-x64` 及 `shared` 分类。
- `mobile/1.2.9/`：上一版安卓安装包与交付资料。
- `source/0.5.1/`：历史源码和网页压缩包。
- `documents/0.5.1/`、`documents/0.5.2/`：原交付脚本、说明及校验资料，仅用于追溯，不应部署到现行服务器。

以上分类内的 `history-for-053.json` 逐项记录原始相对路径、完整大小、SHA256 和有序 `pieces` 列表；二进制内容在 `objects/` 复用、去重，单个分片不超过 32 MiB，分批通过 GitHub Desktop 上传。

恢复原文件时，应下载清单所列的全部分片，逐片验证大小和 SHA256，再严格按 `pieces` 顺序拼接，最后校验完整文件的 `size` 与 `sha256`。分片不是可直接运行的安装包。只有全部批次上传且整文件复核成功后，本机原文件才会清理；私有配置、密钥、数据库及备份不属于公开归档。

## 历史云端包与交付脚本

`cloud/<桌面版本>/` 保存历史云端 ZIP 的脱敏源码快照；无法可靠确定桌面版本的包归入 `cloud/unknown-version/`，保留原包时间戳。`cloud/manifest.json` 记录原包和脱敏包的校验值、来源版本及排除项。这些快照不含生成的安装包、真实配置、数据库、凭据，不应直接部署。

`desktop/<版本>/delivery/` 保存该版交付说明和部署入口；这是历史资料，不要对最新版云端重跑旧部署脚本。所有安装包与源码归档均不证明该版本已完成正式更新签名、云端部署或实机验收。
