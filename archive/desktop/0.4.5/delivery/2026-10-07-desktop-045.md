# 溪泉桌面 0.4.5 操作优化发布

本次只提供 Win10/Win11 的 32 位、64 位安装包。已有 0.4.4 不用卸载，先更新云端，再用原更新私钥签名并发布四个通道；0.4.4 打开后约 15 秒出现更新窗口，下载后覆盖安装。0.4.5 登录页面另外提供“检查更新”。仅上传网页不能更换旧 EXE 内置的页面。

## 已有数据

云端更新只为会员、项目增加归档字段，不清空账号、订单、余额、库存和审计记录。正常开单暂时停用，迁移前后均备份并在隔离 PostgreSQL 17 中实际恢复。优先使用本地已有镜像依赖，不从公网下载 API 基础镜像。资源检查按小内存服务器执行。

强制清空只清当前手牌；清空和删除需验证当前账号自己的密码。会员有余额、剩余次数或未完成交易时不能删除。项目删除是归档，保留历史账单；尚被套票或未结账消费引用时会阻止删除。经营数据重置保留库存数量、包装规格和流水。

## 1. 云端更新

在本机 Windows PowerShell 执行交付目录里的 `01-部署云端.ps1`，不在 ECS 命令行运行 PowerShell。脚本自动识别预检查返回的本次暂存路径，不需要手动粘贴。确认暂停营业写入时按提示输入 `UPDATE 0.4.5`。

成功标记是 `DESKTOP045_API_WEB_DEPLOYED`。此时网页已更新，但桌面更新通道尚未发布。失败时保留 `PRIVATE_DESKTOP_JOB`、`FAILED_PHASE` 和完整输出；不要反复运行旧库存恢复脚本、清除维护标记或恢复数据库。新脚本失败不会自动停掉已健康的 API。

仅在本次任务产生 `ready.json` 后，才支持本次检查点续部署：

```powershell
# 由交付目录 01-部署云端.ps1 加 -Mode resume -Stage <本次路径> -Job <本次路径>
# 本次路径应分别以 desktop045-stage- 和 desktop045-cutover- 开头。
```

## 2. 原密钥签名及联网发布

云端部署成功后，执行交付目录 `02-签名并发布桌面更新.ps1`。按提示填写原来的桌面更新私钥路径；默认路径是 `F:\溪泉发布密钥\desktop-release-private.pem`。每个通道有一次隐藏密码输入，共四次。不要把密码发到聊天里。

先校验线上已有四个通道的签名，自动使用大于旧序号的发布序号。若请求失败或签名异常会停止，不会自动回退到序号 1，不会创建替代密钥。签名后确认上传，四个通道分别校验公共下载内容。安装包没有额外的 Windows 代码签名证书，可能仍显示 Windows 发布者提示；它与应用更新签名不是一回事。

发布成功后完全退出旧桌面 0.4.4，再打开并等待更新提示，不需要先登录。不应先卸载。旧程序必须使用原正式更新密钥及相符的系统/架构通道；如没有提示，发送版本、系统/架构和更新中心的错误。

## 3. 验收

用管理员、库管、收银员分别核验清空一只联动手牌时其它手牌不变、错误密码不能修改数据；有余额会员不能删除、零余额且无次数/欠账会员可以归档；项目名称价格状态可编辑，库存只显示两张统计卡。工作人员仅显示已激活且符合区域权限的手牌，不能开牌。重置前后核对库存结存及流水不变。

本地测试不能替代 ECS 的真实 PostgreSQL 17、原私钥签名或实际 Windows 设备验收；云端和更新通道均需按以上命令由你发布。

## 重新构建（仅需要时）

源码和评审修改提交后，在本机执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "F:\溪泉洗浴系统\scripts\build-desktop-045.ps1" -OutputDirectory "F:\溪泉洗浴系统\桌面045重新构建"
```

构建会使用原公钥、已有本地 Electron 缓存，生成四包和 SOURCE/WEB 压缩包，不会上传。保留原私钥、云端私有配置和备份，不要删除。
